# Content Planner — สรุปงาน "งานค้าง" (Follow-ups) ที่ทำไปทั้งหมด

- **วันที่:** 17–18 พ.ย. 2026
- **สเปกต้นทาง:** `docs/superpowers/specs/2026-11-17-content-planner-followups-design.md`
- **สถานะ:** ขึ้นหน้าจริงครบแล้ว (PR #73–#78 merge แล้ว) Apps Script prod อยู่ที่ @24

---

## 1. ได้อะไร

แท็บ **Calendar** มีช่อง **📌 งานค้าง** สำหรับบันทึกเรื่องที่ยังต้องตามต่อ ทั้งฝั่งเรา (เช่น ส่งรูปเพิ่ม) และฝั่งลูกค้า (เช่น รอ confirm ยอดขาย)

| ผู้ใช้ | ทำอะไรได้ |
|---|---|
| ทีม | สร้าง แก้ ลบ ติ๊กเสร็จ ดูรายละเอียด ผูกกับคอนเทนต์ได้ |
| ลูกค้า (ลิงก์ที่ลงลายเซ็นของแบรนด์) | ดูเฉพาะงานค้างของแบรนด์ตัวเอง ติ๊กเสร็จ และกดดูรายละเอียดเท่านั้น **เพิ่มไม่ได้ แก้ไม่ได้ ลบไม่ได้** |

แต่ละรายการมี: ข้อความ, ฝั่งที่รับผิดชอบ (เรา/ลูกค้า), วันครบกำหนด (ไม่บังคับ), คอนเทนต์ที่ผูก (ไม่บังคับ) ข้อมูลเก็บในชีต `FollowUps` ของ Content Planner

## 3. ส่วนที่ทำ

### Backend (`Content_Planner_GAS/Code.gs`)
- ชีตใหม่ `FollowUps` คอลัมน์: `ID, Brand, ContentId, Text, ResponsibleSide, DueDate, CreatedAt, CreatedBy, DoneAt, DoneBy` (ถือว่าเสร็จเมื่อมี `DoneAt`)
- ฟังก์ชัน: `listFollowUps`, `createFollowUp`, `updateFollowUp`, `toggleFollowUp`, `deleteFollowUp`, `clientToggleFollowUp_`
- `createFollowUp` ผูกกับคอนเทนต์ → ดึง `Brand` จากคอนเทนต์เสมอ ไม่เชื่อ Brand ที่ request ส่งมา
- ลิงก์ลูกค้า (client branch ใน `doGet`/`doPost`) รับเฉพาะอ่านรายการ และ `toggleFollowUp` ส่วน create/update/delete ถูกปฏิเสธด้วย `Action not allowed for client link`
- `clientToggleFollowUp_` เช็ก Brand ของแถวจริงในชีตเทียบกับ Brand ในลิงก์ ถ้าไม่ตรง throw `BRAND_MISMATCH`

### หน้าเว็บ (`content-planner.html`)
- จอคอม: กล่องข้างปฏิทิน เริ่มระดับแถว อา–ส และสูงเท่าตัวปฏิทิน รายการยาวเลื่อนดูในกล่อง
- มือถือ: แถบเลื่อนด้านล่าง กดเปิด/ปิดได้
- กด "+ เพิ่ม" → ฟอร์มสร้างรายการ, กดรายการ → ดูรายละเอียด, รายการที่เสร็จพับไว้ใต้ "เสร็จแล้ว (N)"
- ถ้าโหลดรายการไม่สำเร็จ โชว์ข้อความแดงชัดเจน **ไม่แสดง "ไม่มีงานค้าง" หลอก** (ตามกฎ no silent fallback)
- โหมดลูกค้า: ซ่อนปุ่ม "+ เพิ่ม" และปุ่ม "นำเข้าจากรูปปฏิทิน"

### เทสต์
- `Content_Planner_GAS/test/followups.test.js` ครอบ security checklist ข้อ 1–5 ในสเปก (รวม: ลูกค้าแบรนด์ A ติ๊กของแบรนด์ B ไม่ได้, ยิง create/update/delete ตรงๆ ถูกปฏิเสธ, ContentId ที่ถูกลบไม่ทำให้ error)

## 4. ตรวจหลังขึ้นจริงแล้ว

- **Apps Script prod:** ทดสอบ create/update/toggle/delete และเช็ก brand-scope ด้วยข้อมูลจริงผ่าน
- **หน้าเว็บฝั่งทีม (คอม):** กล่องงานค้างบน = แถว อา–ส, ล่าง = ปลายปฏิทิน
- **หน้าลูกค้า (แบรนด์ PUNTHAI COFFEE, ลิงก์จริง):** ไม่มีปุ่ม "+ เพิ่ม" ไม่มีปุ่มนำเข้า กล่องตรงกับปฏิทิน บนมือถือแถบด้านล่างทำงานปกติ
- **รายการเยอะ:** ทดสอบในเครื่องด้วยรายการจำลอง 25 รายการ กล่องสูงเท่าปฏิทินและเลื่อนในกล่องได้ (ข้อมูลจริงตอนนี้มีงานค้าง 0 รายการ)

## 5. ยังไม่ได้ทำ / ข้อควรรู้

- ยังไม่มีแจ้งเตือน LINE ตอนงานค้างใกล้ครบกำหนด (อยู่นอกสโคปตามสเปก ถ้าต้องการให้ต่อยอดจาก `sendDailyReminders`)
- ตัวตนผู้ทำ (`CreatedBy` / `DoneBy`) แยกแค่ "ทีม" กับ "ลูกค้า" ตามสเปก ไม่มีระบบล็อกอินรายบุคคล
- บนจอคอม ช่องงานค้างไม่ตามเลื่อนหน้า (ไม่ sticky) เพราะสูงเท่าปฏิทินแล้ว บนมือถือยังเป็นแถบติดล่าง
- การเปลี่ยนโค้ด Apps Script ต้อง deploy ด้วย `clasp deploy -i <deployment ID เดิม>` เท่านั้น ห้าม deploy เปล่า (URL จะเปลี่ยน)
